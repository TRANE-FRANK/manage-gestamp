# Principios del Proyecto

## 1. Simplicidad

La solución más simple que resuelva correctamente el problema suele ser la
mejor.

---

## 2. Reutilización

Nunca duplicar código.

Siempre revisar si existe un componente, servicio o helper reutilizable.

---

## 3. Responsabilidad Única

Cada archivo debe tener una única responsabilidad.

---

## 4. Separación de Capas

Page

↓

Service

↓

Repository

↓

Prisma

Nunca romper esta estructura.

---

## 5. Escalabilidad

Toda solución debe pensarse considerando que el sistema seguirá creciendo.

---

## 6. Consistencia

Los nuevos módulos deben seguir exactamente la misma arquitectura que los
existentes.

---

## 7. Legibilidad

El código se escribe para personas.

No para compiladores.

Debe ser fácil de leer incluso meses después.
